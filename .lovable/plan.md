# Host frontend on Vercel (backend stays on Lovable Cloud)

## Good news first
Your app is already a plain **Vite + React SPA** that talks to Supabase over HTTPS. That means the frontend is *already deployable to Vercel today* — nothing about the backend needs to move. Edge functions, database, auth, storage all stay exactly where they are on Lovable Cloud.

The only things missing for a clean Vercel deploy are:
1. A `vercel.json` for SPA fallback (so `/admin/reviews`, `/category/...` don't 404 on refresh).
2. A documented env-var list so the Vercel build has Supabase credentials.
3. A `.vercelignore` so `supabase/` (functions, migrations) isn't uploaded to Vercel — it belongs only on Lovable.
4. A small folder tidy so "frontend vs backend-owned" is obvious at a glance.

## Folder refinement (light, non-breaking)

Your `src/` is already reasonable. Only one meaningful tidy — mirror the `src/apps/admin/` pattern we set up last turn by adding a `src/apps/storefront/` shell:

```text
src/
  apps/
    admin/         AdminApp.tsx  (already exists — admin bundle)
    storefront/    StorefrontApp.tsx  (NEW — groups public routes)
  components/      shared UI (unchanged)
  integrations/    supabase client (unchanged, backend-owned but generated)
  ...
```

`StorefrontApp.tsx` just hoists the storefront `<Routes>` block currently inside `App.tsx`. `App.tsx` then reads as two lines:
```tsx
<Route path="/admin/*" element={<AdminApp />} />
<Route path="/*"       element={<StorefrontApp />} />
```

Benefit for hosting: the admin chunk is already isolated by `vite.config.ts`, and now the storefront entry is a single obvious file — easier to reason about what ships to Vercel.

**I will NOT** move `src/components/`, `src/hooks/`, `src/pages/` around. Mass renames create noise and break imports for no hosting benefit.

## What stays on Lovable
- `supabase/functions/*` (edge functions)
- `supabase/migrations/*` (schema)
- Database, auth, storage
- `src/integrations/supabase/client.ts` + `types.ts` are auto-generated by Lovable — don't touch, but they're bundled into the frontend build (correct).

## Deploy flow after this change
1. Push repo (via Lovable's GitHub sync, if not already connected).
2. On Vercel: New Project → import repo → framework auto-detects Vite.
3. Add the 3 `VITE_SUPABASE_*` env vars (copy from Lovable `.env`).
4. Deploy. Point `poshplexbd.com` DNS at Vercel.
5. Keep editing in Lovable — every push auto-deploys to Vercel; backend keeps deploying to Lovable Cloud automatically.
